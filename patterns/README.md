# Patterns

Patterns are practised independently of production code. The goal is active implementation, not reading.

## How to learn a pattern actively

1. Read the problem and the canonical structure only.
2. Implement it yourself in a scratch file (under `.scratch/` or a separate practice location), without looking at the canonical example.
3. Compare with the canonical version and note the differences.
4. Implement one variation, and one language if it is useful.
5. Write down failure cases you hit, and when you would not use it.

Practising a pattern never introduces it into the application. That is a separate, deliberate decision recorded in `docs/decisions/`.
