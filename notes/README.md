# Notes

Practical knowledge captured while developing. Each note is one concept.

## When to create a note

- You learned something non-obvious while implementing or debugging.
- The same question came up twice.

Do not create notes just to have them.

## When to update

If a note exists for the concept, update it instead of creating a duplicate.

## Organisation

Flat files, named by concept: `<domain>-<concept>.md`, e.g. `kubernetes-probes.md`, `spring-scheduled.md`. Use the domain as a prefix to keep related notes together.

## Index

- `gradle-files.md` — Gradle file structure and comparison to Maven
- `gradle-toolchain.md` — JDK toolchain configuration and why two JDKs exist
